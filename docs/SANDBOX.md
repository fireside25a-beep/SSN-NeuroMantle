# Local process isolation

The module, local AI adapter and five-qubit certificate verifier run as forked children. Before executing a child, NeuroMantle closes inherited descriptors above standard streams, clears the environment, sets a minimal executable path, changes its working directory to `/`, disables core dumps and regular-file output, sets `no_new_privs`, and installs a Linux seccomp BPF filter. If any required step fails, the child exits before executing the supplied program. The parent refuses its result. `ai-run-socket` explicitly preserves only FD 3, a connected Unix stream created by the parent for a named local service.

The filter checks the syscall architecture and blocks x86-64 x32 calls. It refuses file mutation operations, writable `open` and `openat`, `openat2`, sockets and connection calls, process creation and signaling, tracing, mounts, namespace creation, `io_uring`, BPF and other listed escape primitives. An `ioctl` returns `ENOTTY`, which lets Python identify ordinary script files without granting device control. The child can write its bounded protocol response through standard output, but its standard error goes to `/dev/null`.

The adversarial test runs a compiled C program as both a routed module and an AI adapter. It tries to truncate, create and delete a real test file, create a directory, open IPv4 and Unix sockets, allocate System V shared memory and fork. Every operation returns `EPERM`; the file remains byte-identical. Ordinary C and Python component tests and the Surreal certificate check still pass under the filter.

This policy protects against those classes of mutation and network calls. **It does not hide readable host files.** A program may read files already accessible to the caller and may reveal data in its bounded standard output. A granted FD 3 also allows arbitrary messages to its local service. The filter does not create a mount namespace, user namespace or container. For untrusted or confidential workloads, run the whole framework under a separately configured container or virtual machine with explicit read mounts. The user-facing `dev` and `compile-vanta` commands can build projects and are not run under this filter.

The filter supports reviewed Linux x86-64 and AArch64 syscall ABIs. A kernel or parent sandbox that refuses seccomp installation causes process admission to fail closed. The source and tests are in `core/neuro_sandbox.c` and `tests/sandbox_integration.py`; [SYSTEM_INTERFACE.md](SYSTEM_INTERFACE.md) lists the calls involved. This is a real process restriction, not a proof that arbitrary code is harmless.
